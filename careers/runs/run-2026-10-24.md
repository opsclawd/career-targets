## Method

1. Read `careers/careers_registry.csv` (391 data rows) and `careers/jobs_registry.csv` (813 data rows) before updating.
2. Re-checked all 129 known ATS boards (Ashby, Greenhouse, Lever, Workday, Workable, SmartRecruiters, Jobvite, ICIMS, BambooHR, Taleo, SuccessFactors, Dover) scraped to 7,894 raw postings (`/tmp/recheck_all.json`).
3. Scraped Built In Calgary company/job boards (714 postings) and used ATS-board back-detection to find the canonical ATS page for each company board rather than the aggregator URL.
4. Probed ATS boards for newly discovered company names from Built In Calgary and from directory scans (`/tmp/probe_hits.json`, `/tmp/dir_probe_hits.json`, `/tmp/builtin_probe_hits.json`).
5. Title filter: senior/staff/principal/lead + software/backend/full stack/platform/SRE/data/AI-ML engineering. Rejected management, mobile-only, test/QA-only, crypto/Web3, product, sales, support, data-analyst, intern/junior, and staffing/consulting roles.
6. Location bucketing: Calgary -> `Calgary AB`, Alberta -> `Alberta AB`, explicitly Canada-remote -> `Remote Canada`. Explicit non-Calgary Canadian offices and US-only roles excluded.
7. Deduped by exact job URL first, then normalized `company + title + location`; ATS-derived rows preferred over Built In Calgary rows for the same role. No overlap with existing registry rows (0 URL collisions, 0 title/location collisions).
8. Verified all 136 new URLs (14 careers pages + 120 job links + registry-side corrections) return HTTP 200; corrected one dead Built In Calgary board URL (`praia-health` -> `praia.com/careers`) and one aggregator careers URL (`Akamai Technologies` -> `akamai.com/careers`).
